# LangSteps v1.2.0 — TypeScript Curriculum Modernization

**Status:** Active development on `release/v1.2.0`; **not tagged, merged or published**.
**Starting point:** Stable v1.1.1.
**Site:** https://sanskarin.github.io/LangSteps/

## Implemented in the development branch

- Extracted browser-local course progress persistence into strict `src/curriculum/progress.ts`.
- Added `src/curriculum/navigation.ts` for safe lesson hash parsing and guided previous/next navigation.
- Migrated the complete lesson viewer into strict `src/curriculum/learning.ts`, compiled to `curriculum/learning.js` without changing the public lesson URLs or progress keys.
- Added an accessible `src/curriculum/donation.ts` controller, replacing copied inline donation JavaScript on ten Privacy/Terms pages.
- Restored the broken Web APIs Reference in stable PR #8, then rebuilt it for v1.2.0 as a progressively enhanced **15-entry static reference** with searchable examples, category filters, native keyboard-accessible `<details>`, compatibility/permission notes and official MDN links.
- Added strict `src/curriculum/api-reference.ts`, compiled to `curriculum/api-reference.js`, for filtering, clear/reset, visible-entry counts, expand/collapse, empty results and `/`-to-search shortcuts.
- Added regression tests for static API entries without JavaScript and the TypeScript filter/keyboard behavior.
- Added Razorpay, Buy Me a Coffee and PayPal buttons to those ten donation dialogs through the stable-site hotfix PR #7.
- Compiled all four browser modules into dependency-free `curriculum/*.js` assets, preserving the static GitHub Pages architecture.
- Integrated the new scripts with all three new curricula: Go, SQL and C#.
- Preserved the existing `langsteps:v1.1.0:mastery:<slug>` storage keys so 1.1.x learner achievements survive.
- Expanded Node regression coverage for progress validation, storage denial, deep links, course navigation, modal keyboard trapping, Escape/outside dismissals and all provider links.
- Precached all compiled lesson scripts and key Privacy/Terms pages using a distinct v1.2 development cache, without deleting other projects' caches.
- Added a strict TypeScript-only compile configuration and CI drift check that compares regenerated JS with committed browser assets.

## Curriculum schema hardening (22 October 2026)

- Added ambient TypeScript declarations in `src/curriculum/course-schema.d.ts` for `LangStepsCourse` and `LangStepsLesson`. The typed browser viewer now consumes the same declarations instead of maintaining its own copy.
- Added `scripts/validate-curricula.cjs`, a dependency-free validator for `Go/data.js`, `SQL/data.js` and `CSharp/data.js`. It parses the single JSON-literal assignment **without executing the source**; arbitrary expressions and trailing JavaScript are rejected.
- CI now rejects missing or unsupported course/lesson properties, blank or non-string fields, duplicate titles/IDs, unsafe fragment IDs, invalid difficulty labels, and a mismatched course slug.
- Added regression tests for valid published content, schema parity, malformed records, duplicates and executable source rejection.
- Run `npm run validate:curriculum` before publishing edited lessons. These checks do not change public lesson URLs, the number of published lessons, browser storage keys, or the optional ASP.NET Core backend.

## Real-browser release smoke checks (22 October 2026)

- Added a Playwright Chromium test runner in `playwright.config.cjs` with a local Python static server; no cloud/API service is required.
- Automated browser checks cover rendering/search for all three guided courses, existing localStorage mastery keys after reload, hash/back navigation, native Web API cards with JavaScript disabled, accessible API search/filter controls, donation dialog choices/focus restoration, a narrow mobile viewport, and an offline service-worker reload.
- Added `tests/browser/smoke.spec.cjs` and a separate `Browser Smoke — Chromium` pull-request workflow. Browser traces and screenshots are uploaded when tests fail.
- To run locally: `npm install`, `npx playwright install chromium`, then `npm run test:browser`. Install compatible OS libraries if Chromium requests them.
- Chromium automation is **not** a substitute for final manual checks in Firefox/Safari, real mobile browsers, keyboard navigation, or screen reader testing.
- Runtime remains a static GitHub Pages site; Playwright is a development-only test dependency.

## Reproducible development

```bash
npm install
npm run validate:curriculum
npm test
npm run typecheck
npm run typecheck:curriculum
npm run build:curriculum
git diff --exit-code -- curriculum/progress.js curriculum/navigation.js curriculum/learning.js curriculum/donation.js curriculum/api-reference.js
dotnet build server/LangSteps.Server/LangSteps.Server.csproj -c Release
```

**Source of truth:** Edit the TypeScript files under `src/curriculum`, then run `npm run build:curriculum` and commit the changed `curriculum/*.js` output. Do not hand-edit the generated JavaScript. These output files are retained in Git because the GitHub Pages website must run without requiring a user-side build step.
