# LangSteps v1.1.0 — Release Notes

**Target tag:** `v1.1.0`  
**Release title:** `LangSteps v1.1.0 — Go, SQL & C# Learning Paths`  
**Release type:** minor feature release  
**Target website:** https://sanskarin.github.io/LangSteps/

## Highlights

LangSteps expands from seven released learning paths to **ten**. The original HTML, CSS, JavaScript, React, Python, TypeScript and Rust modules remain available, and three new guided paths join the platform:

- **Go:** 15 lessons covering variables, collections, interfaces, error handling, goroutines, channels, contexts, tests and HTTP services.
- **SQL:** 15 PostgreSQL-oriented lessons covering table design, SELECT, JOIN, aggregation, windows, transactions, indexing, constraints and injection-resistant parameter binding.
- **C# 13 / .NET 9 / ASP.NET Core:** 15 lessons covering types, records, LINQ, async/await, cancellation, Minimal APIs, dependency injection, CORS and tests.

All three paths include search, category filtering, worked examples, exercises, copy-to-clipboard, navigation by URL fragment and **local progress tracking**. Lesson progress is stored only in the browser's localStorage.

## Engineering improvements

- Linked all three live paths from the homepage, instead of displaying roadmap-only placeholders.
- Synchronized the ASP.NET Core module catalog and TypeScript offline catalog.
- Fixed project-relative service worker precaching for GitHub Pages at `/LangSteps/`; all three new paths and their assets are preloaded once the service worker has installed.
- Updated the web app manifest, package version and release metadata.
- Replaced a placeholder `npm test` command with real Node tests for routing, lesson content, JavaScript syntax, and feedback API privacy.
- Added a workflow to run curriculum tests, TypeScript type checking, TypeScript compilation and an ASP.NET Core Release build.
- Restricted browser CORS origins for the optional server, removed the unauthenticated feedback-list endpoint and aligned reported module statistics with actual catalog entries.
- Stopped reporting simulated execution output as successful compilation or code execution.

## Platform requirements and important limitations

The website on GitHub Pages is **static**. It serves lessons, snippets, quizzes and locally stored progress; **it cannot run ASP.NET Core APIs** or compile Go, SQL or C# code. The .NET server remains an optional separately hosted component. The execution API returns a clear unavailable result until a properly isolated code runner is implemented. The new lessons use examples for learning; they do not claim to execute code in the browser.

The new content uses 15 curated lessons per path. Older documentation advertised higher planned lesson counts; those figures should not be used as release-complete counts without an audit. Old curricula outside the precache may need a first online visit. Existing legacy pages and features should be manually regression-tested on mobile and desktop.
